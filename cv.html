Going back to finished work

Several of my projects were already submitted and marked when I returned to them. Each time I reviewed the work as a critic would, wrote down what was wrong, and rebuilt it, keeping the original public so the difference can be seen.

Wind turbine predictive maintenance

MSc dissertation, marked 80% · rebuilt as v2

Found: parts of the evaluation were more generous than an operator would get: thresholds set on the events being scored, training data chosen using test labels, and an unverified scoring function.

Did: rebuilt it from scratch so no number depends on information an operator would not have had, tested the scoring code against the benchmark authors' reference, and added confidence intervals. The score fell from 0.655 to 0.619, and I report the lower one.

Fuel system condition monitoring

Digital Twins module, marked 76% · rebuilt as a digital twin project

Found: a reversed severity axis, a pump model checked on its own training data and then used outside its speed range, a sign error in the app, and healthy limits set on raw samples. Every fault was also recorded at a different time of day, so a clock alone could name it 96% of the time.

Did: fixed each one and rebuilt the analysis around tests the clock cannot pass: physics indicators fitted without the fault being scored, and a classifier trained only on simulated faults.

Password protection system

Early notebook prototype · rewritten

Found: the prototype worked but was not secure.

Did: rewrote it as a tested package with hashed and salted passwords, self-expiring lockout and recovery.

Subway gate motor remaining life

PHM Europe 2026 Data Challenge · audited after release

Found: a flaw in the degradation-step detector, and one result that the statistics did not support.

Did: fixed the detector, re-ran the analysis and restated the unsupported result as unproven.
