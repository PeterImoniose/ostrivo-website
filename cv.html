01 · Profile

Engineering data, business questions, honest answers

Data scientist with an MSc in Applied Data Science in Engineering and a BSc in Industrial Mathematics. I work across the whole data workflow: auditing and cleaning messy data, building Python and SQL pipelines, modelling, and reporting through dashboards and presentations that non-technical people can act on.

03 · Going back to finished work

Submitted, marked, and then improved

Several of these projects were already handed in and marked when I went back to them. I reviewed each one as a critic would, wrote down what was wrong and rebuilt it, keeping the original public so the difference can be checked. Switch each card between Before and After.

Wind turbine predictive maintenance

MSc dissertation, marked 80%
Original
0.655
Rebuilt
0.619
0.50 chance0.66 published
What I found
  • Thresholds and training length set by hand on the same events that were then scored.
  • Test labels decided which data a model was trained on.
  • A hand-written, unverified version of the benchmark's scoring function.
What I did
  • Rebuilt from scratch so no number uses information an operator would not have had.
  • Tested the scoring code against the benchmark authors' reference on random inputs.
  • Added bootstrap intervals and three seeds. The score fell to 0.619, and I report it.

Fuel system condition monitoring

Digital Twins module, 76%
96%accuracy from the clock alone: every fault was recorded at a different time of day
What I found
  • A reversed severity axis and a sign error in the app.
  • A pump model checked on its own training data, then used outside its speed range.
  • Healthy limits set on raw samples, 2 to 14 times too wide.
What I did
  • Fixed each one and rebuilt the analysis around tests the clock cannot pass.
  • Physics indicators fitted without the fault being scored tell all five faults apart.
  • A classifier trained only on simulated faults scores macro F1 0.87 on the real rig.
